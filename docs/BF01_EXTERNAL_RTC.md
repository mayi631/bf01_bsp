# BF01 小核只读 BM8563

## 接线与读取范围

依据应用仓库的 `RTC/C269877_BM8563ESA_2022-07-28.PDF` 第 1、7–10、14–15 页，
以及 U1-3 原理图：

| 项目 | 配置 |
| --- | --- |
| 控制器 | IIC1，100kHz，七位寻址 |
| SCL | PAD_MIPI_TXP2，B5，IIC1_SCL |
| SDA | PAD_MIPI_TXM2，A5，IIC1_SDA |
| 地址 | 0x51；线上写地址 0xA2，读地址 0xA3 |
| 控制状态 | 0x00–0x01，用于检查 STOP |
| 时间 | 0x02 秒/VL、0x03 分、0x04 时、0x05 日、0x06 星期、0x07 月/世纪、0x08 年 |

实现位于 BF01 定制的 `src/bf01_boot_rtc.c`，不是通用 SDK IIC 驱动补丁。
开机在 `PLATFORM_IoInit()` 完成引脚复用后，由 `APP_BootCapturePrepare()` 读取一次，
位于控制台初始化之后、媒体初始化之前，保证真实读取结果进入小核日志；
成功、失败均释放控制器，不在 Linux 运行期间周期访问 IIC1。现有启动顺序中小核先于
U-Boot/Linux 运行；如果后续改变双核启动顺序，需要重新核对 IIC1 访问所有权。

使用 SDK CSI 完成控制器初始化/释放，板级轮询完成单次连续读：
发送寄存器指针 0x00，首个读命令带 RESTART，预先排入九个读命令后再收取数据，
仅在最后一字节发送 STOP。BF01 控制器 RX/TX FIFO 均为 64 字节。
不能每发送一个读命令就等待该字节接收完成：板端实测该方式在首字节卡住，
控制器保持 SCL 为低，20ms 后超时，后续 Linux 访问也会一直报告总线忙。
不调用当前 SDK 中逐字节发 STOP 的 `csi_iic_mem_receive()`，不修改摄像头 IIC3 驱动。
传输状态等待共用 20ms 预算；NACK/abort/超时退出时单次复位 IIC1 控制器并释放，
不复位外部 RTC，不做复位循环或无限重试。
只发送读所需的地址指针，不写 BM8563 时间、控制、VL、闹钟或定时器寄存器。

## 时间链路

BM8563 的 BCD、世纪位（C=0 为 20xx，C=1 为 19xx）、星期范围、闰年和月日均校验。
STOP、VL 或无效日期不会作为可信时间使用；有效范围沿用原时间戳的 2020–2099 年。
读取成功打印原始寄存器、日历时间和耗时。日历先按独立的存储时区转换为 UTC，
由水印以此次读取值加小核 64 位单调计时器经过的秒数走时，不再依赖片内 RTC 写后回读。
原有 JPEG/录像水印开关、格式、显示时区以及 Linux IPC 校时消息保持不变。
失败保留原片内 RTC/Linux 校时路径，不阻止拍摄，也不编造日期。

外部芯片没有时区字段，应用 INI 的 `[boot_timestamp]` 新增
`external_rtc_utc_offset_minutes`，由现有生成脚本嵌入小核。当前板端实读为北京时间，
默认 `480`；芯片确实存 UTC 时设为 `0`。该参数只解释存储日历，不改变显示时区。
Linux 校时仍只写片内 RTC，**不会写回 BM8563**；外部芯片首次设时不在本次范围内。
硬件确认成功后同步刷新水印的软件时间基准，确认失败仍返回原有错误，不能假报成功。
即使关闭水印，也会读取外部 RTC 并打印，但不因此创建水印或更改开关。

小核的镜像。本次没有修改 Linux、osdrv 或应用业务代码，仅重编 osdrv/应用不生效。

烧录后检查 `[boot-rtc]` 的原始寄存器、`stored_utc_offset_minutes`、`utc_seconds`、`errno=0` 和释放日志，
再核对三张照片和录像时间戳、跨秒更新、Linux 校时和冷启动时间保持。
VL/STOP、芯片未应答和异常日历必须保持拍录可用且明确报错。
