# BF01 / ATBM6461 Wi-Fi 吞吐率测试记录

测试日期：2026-10-10。以下结果来自实际板端 ADB 测试，不是估算值。

## 1. 依据与测试限制

参考 `/home/mayi/CV184X_ALLPDF/CV184x_software_documents_zh/Wi-FiUserGuide_zh.pdf`
第 7.1 节、印刷页码 21～22：使用 iperf3，TCP 测试 10 秒，
UDP 测试参数为 `-t 10 -u -b 100M -l 32k`。

指南要求：PC 通过以太网连接路由器，板子通过 Wi-Fi 连接同一路由器。
当前 PC 的有效地址在 WLAN，未发现具有有效局域网地址的有线接口，因此本次只能作为
**当前环境的参考测试，不能作为严格符合指南拓扑的性能验收，也不能视为模组极限吞吐率**。

实际链路为 PC 的 WSL2 → Windows 网络/NAT → PC Wi-Fi → 路由器 → BF01 Wi-Fi。
为避免修改 Windows 端口转发及防火墙，本次板子统一作为 server，PC 使用普通方向测试
板端接收，使用 `-R` 测试板端发送。数据方向正确，但发送测试的 client/server 角色
与指南中的示例不同。正式复测应采用第 5 节的原始角色和有线 PC。

## 3. 实测结果

TX = BF01 → PC；RX = PC → BF01。吞吐率取实际接收端结果，单位为 Mbit/s，
不是 MB/s。每项为一次 10 秒测试，并非多次平均。

| 测试 | 参数 | 接收端吞吐率 | 接收端丢包统计 |
| --- | --- | ---: | --- |
| TCP TX | 默认 TCP，反向发送 | 3.93 | TCP 不使用 UDP 丢包统计 |
| TCP RX | 默认 TCP | 6.51 | TCP 不使用 UDP 丢包统计 |
| UDP TX（指南参数） | 100M / 32768 字节 | 0，未收到有效测试数据 | 无有效统计，显示 0/0 |
| UDP RX（指南参数） | 100M / 32768 字节 | 0，未收到有效测试数据 | 无有效统计，显示 0/0 |
| UDP TX（补充） | 1M / 1400 字节 | 1.00 | 0/893，0% |
| UDP RX（补充） | 1M / 1400 字节 | 1.00 | 0/893，0% |
| UDP TX（补充） | 10M / 1400 字节 | 4.84 | 0/4322，0% |
| UDP RX（补充） | 10M / 1400 字节 | 10.0 | 1/8928，0.011% |
| UDP TX（大包降速补充） | 1M / 32768 字节 | 0，未收到有效测试数据 | 无有效统计，显示 0/0 |
| UDP RX（大包降速补充） | 1M / 32768 字节 | 0，未收到有效测试数据 | 无有效统计，显示 0/0 |

TCP RX 客户端汇总为 6.51，板端完整接收区间汇总为 6.50，差别来自结束区间及舍入。
UDP TX 请求 10M 时发送端汇总约 5.15，不能把设置的 10M 当成实际发出的速率。

**UDP 的 `sender=100M` 不代表接收成功；`receiver=0`、`0/0` 也不代表零丢包通过。**
本次指南中的 32KB UDP 测试没有通过，不能据此宣称 Wi-Fi 全部性能项正常。

## 4. 结论与未确认的问题

- TCP 双向测试可完成；1400 字节 UDP 双向也可完成。
- 同样 1M 目标速率下，1400 字节成功而 32768 字节没有有效接收，说明问题具有
  明显的报文大小相关性，不仅是请求 100M 超过当前吞吐率。
- iperf3 明确警告 32768 字节超过路径 MSS，可能造成分片/丢包。
  这提示需要检查 IP 分片路径，但尚不能确定故障位于模组固件、Linux 驱动、路由器
  还是 Windows/WSL NAT；本次未抓取双端分片包，不能直接判定根因。
- PC 同样走 Wi-Fi，板端扫描 RSSI 为 -79，且经过 WSL NAT；当前数值不能作为
  该芯片或 SDIO 配置的性能上限，也不能据此要求直接提升 SDIO 时钟。
- 测试结束后仍保持 HOWNICE 连接，公网 ping 3/3 成功；测试 server 已退出。

下一步先换成有线 PC、原生 iperf3，保持当前驱动/模组固件不变复测。
如果 32KB UDP 仍无接收，再分别抓取发送端与接收端数据，检查分片是否发送、到达和重组，
并将原始日志及模组固件版本交给 ATBM 厂商。不要只依据本次现象修改驱动。

## 5. 严格按指南复测的命令

将 PC 用网线接入同一路由器 LAN 口，确认有线 IP；不要用 WAN 口。
`PC_IP` 必须替换为实际有线地址，不能继续沿用旧 WLAN 地址。
PC 端需有原生 iperf3，并仅针对测试工具/端口按系统要求允许局域网 TCP/UDP 5201，
不要关闭整个防火墙。每项测试单独执行，测试间隙不要扫描 AP 或执行其它流量测试。

### 板端发送：PC 做 server

PC 执行：

```sh
iperf3 -4 -s -p 5201 -i 1
```

板端依次执行：

```sh
PC_IP=192.168.10.XXX
/mnt/data/iperf3 -4 -c "$PC_IP" -p 5201 -t 10 -i 1
/mnt/data/iperf3 -4 -c "$PC_IP" -p 5201 -t 10 -i 1 -u -b 100M -l 32k
```

### 板端接收：板端做 server

停止上一项 PC server。板端执行：

```sh
/mnt/data/iperf3 -4 -s -p 5201 -B 192.168.10.130 -i 1
```

PC 依次执行（板端地址变化时替换）：

```sh
iperf3 -4 -c 192.168.10.130 -p 5201 -t 10 -i 1
iperf3 -4 -c 192.168.10.130 -p 5201 -t 10 -i 1 -u -b 100M -l 32k
```

server 是前台命令，测试结束用 Ctrl+C 停止。UDP 未通过时，保持其它参数不变，
额外比较 `-b 1M -l 1400` 与 `-b 1M -l 32k`，不要将补充小包测试冒充指南原始大包结果。
正式记录建议每项重复三次，保存 sender/receiver 汇总、UDP 丢包、RSSI、距离和 AP 型号。
