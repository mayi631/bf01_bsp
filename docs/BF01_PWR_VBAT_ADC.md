# BF01 小核启动电压采样与 RTC 初始化

## 当前交付状态

板级 `custom_platform.c` 当前设置 `BF01_PWR_ADC_LOW_CHECK_ENABLE=1`、`BF01_PWR_ADC_LOW_MV=0`。小核在 `PLATFORM_IoInit()` 中采样一次 `PWR_VBAT_DET`，失败时继续启动，不增加常驻监测任务。

采样后的 `mv` 是无符号数，阈值为 0 时不会满足 `mv < cutoff`，因此当前保留电压采样，但不通过这条判断触发低电关机。不能将它描述为已经启用有效的电池低电保护，也不能说 ADC 采样没有执行。之前“检测关闭、阈值 1000mV”的说明与当前源码不符，以本说明为准。

这里只核对源码及补丁，不代表当前板端已经烧录同一小核和 FSBL，也不代表已经完成电源或低电保护验收。

## 采样路径

- BF01 接线使用 `PWR_VBAT_DET / PWRSAR.VIN3`，RTC ADC 基址为 `0x0502c000`。
- CSI ADC 设备编号为 1，通道为 3；不能直接照搬 DC100 的 ADC 设备编号。
- 采样按 `raw * 1500 / 4096` 换算为 ADC 引脚电压，保留 EFUSE 校准及采样后的停止、释放流程。
- 1500mV 参考值、12 位换算以及电池分压比例仍需实测核对。ADC 引脚电压不等于电池端电压，不能直接用电池截止电压替换阈值。

## 0043：ADC 驱动适配

`patches/0043-cvi_alios--fix-adc-rtc-channel-selection-and-timeout.patch` 修改公共小核 ADC 驱动：

1. 放开 RTC ADC 通道 3；原驱动在设备 1 上拒绝通道 3，板级低电采样无法完成。
2. 通道选择、占用检查、关闭和释放统一使用已有的 `ADC_CHANNEL_SEL_CH(channel)`，即 `1U << (4 + channel)`。旧的 `channel << 5` 对通道 3 会选中多个错误位。
3. 先验证通道范围再计算位掩码；占用检查只用于启用请求，关闭时不再套用启用占用条件。
4. 释放时只清除当前有效通道的选择位，保留其他通道，不关闭整个共享 ADC 控制器。
5. 同步读取使用 `csi_tick_get_ms()`；超时从 1000000 改为 1000 毫秒，避免无数据时等待约 1000 秒。

这是公共驱动行为修复，不只影响 BF01。没有改 Linux ADC、DTS、AI、拍照、SDIO 或运行期间的 GPIO29 关机监测。

## 0044：RTC 电压检测控制寄存器默认值

`patches/0044-fsbl--fix-rtc-clear-power-vbat-detect-control.patch` 将 `set_rtc_en_registers()` 中对 `RTC_EN_PWR_VBAT_DET`（`0x050260d0`）的初始化从仅清 bit 2 改为整字写 0，固化此前要求的寄存器值，而不是依赖每次 ADB 手工写寄存器。

这与 ADC 通道采样是两条不同路径：ADC 修改控制采样，FSBL 修改控制启动阶段 RTC 寄存器初值。不能据此宣称已经证明现场掉电由这个寄存器引起。

该修改位于公共 CV181X 初始化函数，未增加 BF01 专用条件；所有执行该初始化的 CV181X 构建都会写零。它不保留该寄存器其他位，复用于其他板型前必须核对对应电源设计。只替换 Linux 应用不会更新 FSBL，也不会改变这个寄存器的启动默认值。

## 构建与验收边界

- ADC 修改需要重新编译小核，RTC 初始化修改需要重新编译 FSBL，并按 SDK 流程重新生成、打包相关 FIP/小核镜像；仅编译 osdrv 或应用不会生效。
- 串口核对 `PWR_VBAT_DET raw=..., pin=...mV, cutoff=0mV`，并用万用表对照引脚实际电压。读取 `0x050260d0` 核对启动默认值时，也需确认后续软件是否改写。
- 当前不改变阈值、不重新启用有效低电关机，不通过手工改 ADC 或 RTC 寄存器代替验证。
- 正常供电启动、ADC 读取失败、不同供电端以及 GPIO29 正常关机需要真实板端回归。若以后启用有效低电阈值，还需验证临界电压和 RTC 请求是否能够按板级电路真正断电。
